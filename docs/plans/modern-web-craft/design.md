# Modern web craft

## Outcome and boundaries

Help Hermes turn a subject-specific design premise into a working contemporary interface. Keep the installed runtime standard-library-only, all five native tool names, all sixteen style IDs, and old direction calls compatible. No model calls, live activation, credential changes, package release or merge are part of this change.

## Reference layer

Add allowlisted `layout`, `platform` and `performance` topics. The platform response contains its Markdown guidance and a small versioned feature ledger from `data/platform-features.json`. Each entry identifies an exact capability, design purpose, progressive-enhancement fallback, detection, constraints, verification and primary source with a check date. Availability is guidance for choosing a target, not a promise about the caller's browser. Centralize topic names so native schemas and lookup cannot drift.

## Direction context

`make_direction(brief, surface="product", authority="greenfield", styles=None, context=None)` accepts an optional object. String fields: `audience`, `identity`, `browsers`, each nonblank and at most 2,000 characters. List fields: `tasks`, `content`, `assets`, `constraints`, each 1–12 nonblank strings of at most 1,000 characters. Total context text is at most 16,000 characters. Reject unknown fields and invalid types without coercion. Preserve supplied text and copy lists to avoid aliasing caller state.

Add `context`, `design_contract`, `craft_references` and `verification_matrix` to successful packets. A contract is explicitly awaiting host authorship, not generated design judgment. It asks for a subject thesis and proof artifact, structural alternatives (or preservation rationale), compositional invariants, meaningful signature, mobile transformation, support/performance budget and a subject-swap critique. Missing-context prompts reflect fields actually supplied. Default candidate selection and explicit styles remain unchanged; no keyword-based taste ranking.

## Demonstration

Improve Set's existing print-room workbench first. Preserve all content, navigation, filtering, session edits and JavaScript-off behavior. Make the source readable. Use container-responsive topology and metadata alignment, rem-inclusive fluid type, wrapping, visible focus and forced-colors treatment. Useful layout works without enhancements. Ordinary task changes remain immediate. Add no remote fonts, frameworks or decorative control.

## Evidence

Add behavioral tests for context validation, native schema/dispatch, source and installed-package resources. Extend existing browser tests with 320/390/768/1440 layouts, a narrow embedded container, text resizing, long content, forced colors, RTL, reduced motion and disabled-enhancement fallback. Keep modern-color paint unknown in the conservative contrast helper. Full package tests, independent review and terminal PR CI status precede publication claims. Real native dispatch runs only with isolated HOME/HERMES_HOME.

Prompt effectiveness, artistic superiority, screen-reader usability and field Core Web Vitals remain unmeasured. Use task scripts, screenshots and stated judgments, never numerical beauty scores.
